> 2026 가천대학교 창의적 종합설계 아이디어 공모전 출품작
> 3조 | 강현서 · 성준하 · 이채원 (지도: 한형석 교수님)
> 기준 코드: `firmware/cargo_guardian_code_v6.ino` (GitHub `Billiardchalktheif/Cargo_gaurdian_system`, `main` 브랜치 최신판)
> 실험 근거: `화물지킴이_실험데이터_분석보고서.md` (업로드 반영, 2026-08-31)

## 1. 개요

고속도로 화물차 낙하물 사고를 예방하기 위한 실시간 화물 적재 상태 감지 및 단계별 경보 시스템. 화물 결박 불량, 급제동·급커브로 인한 화물 쏠림이 낙하물 사고의 주요 원인이라는 점에 착안해, 운전자가 주행 중 화물 이상 징후를 실시간으로 인지하고 사전에 대응할 수 있도록 설계했다.

기울기(자이로)·장력(로드셀)·위치 이탈(거리 센서) 3종 데이터를 절대값이 아닌 **영점 대비 변화율(%)**로 정규화해, 화물의 종류·무게와 무관하게 동일한 임계값을 적용할 수 있도록 설계한 것이 핵심 특징이다.

## 2. 기획 배경 (아이디어 심사 발표자료 기준)

> 아래는 최초 아이디어 심사 때 제출한 발표자료(2026-1학기 캡스톤 디자인) 내용. 이후 하드웨어·알고리즘은 계속 발전했지만, **문제인식·기대효과 등 기획 논리는 신청서/과제보고서 서두에 그대로 활용 가능**.

- **문제 인식**: 고속도로 낙하물 수거 현황은 연간 약 20만 건('18~'22년 19.8만~25.7만 건 수준)이며, 낙하물 관련 사고도 연 40~57건씩 꾸준히 발생(사상자 발생 연도 다수). "고속도로 낙하물 피해 2,285건 접수, 실제 보상은 단 7건" 등 언론 보도로 문제의 심각성과 사각지대를 뒷받침
- **5 Why 분석 결론**: 적재함과 운전석이 분리돼 있어 운전자가 육안으로 화물 상태를 확인할 수 없고, 이를 실시간으로 감지할 저비용 전자 장치가 기존에 없었다는 점을 핵심 원인으로 도출
- **기대효과 4가지**: ① 안전성 향상(낙하 사고 가능성 저감) ② 실시간 모니터링 보조(운전자가 직접 확인 못 하는 적재 상태 보조 감지) ③ 경제적 손실 감소(화물 파손·사고처리 비용 절감) ④ 확장성(향후 데이터 기반 적재 가이드·위험 패턴 분석으로 확장)
- **초기 센서 선정 비교**: 자이로는 BNO055(3종 센서 통합, 가공된 데이터 바로 출력)를 1차 채택했으나, 이후 실제 구현 단계에서 **MPU6050**으로 최종 변경(원가·확장성 등 실험 결과 반영). 장력 HX711(저렴+온도 오차 적음), 거리 VL53L1X(4m 장거리형)는 최초안 그대로 유지
- 최초 시스템 구성(발표자료 기준)은 Arduino Uno + LCD 16×2였고, 이후 v6에서 **ESP32 + LCD 20×4 + MPU6050×4**로 고도화됨 — 서류에는 반드시 v6 최신 스펙 기준으로 작성

## 3. 하드웨어 구성 (v6 최신)

| 구분 | 내용 |
|---|---|
| 메인 컨트롤러 | ESP32 (Arduino 아님 — Wi-Fi 내장) |
| 기울기 센서 | MPU6050 자이로 **4개**, TCA9548A I2C 멀티플렉서로 좌/우 각 2개씩 연결 |
| 장력 센서 | HX711 + S형 로드셀 (래싱벨트 장력 변화 감지) |
| 거리 센서 | VL53L1X (적외선 장거리형, 화물 위치·이탈량 감지) |
| 디스플레이 | LCD 20×4 (I2C) — v2의 16×2에서 확장 |
| 출력 | 능동형 부저 (경고/위험 단계별 차등), 리셋 버튼, 음소거(MUTE) 버튼 |
| 전원 | 보조배터리(USB 5V) — 컴퓨터 없이 독립 동작 |
| 통신 | Wi-Fi(UDP)로 실험 데이터를 PC에 실시간 전송 → Python 스크립트가 엑셀로 자동 저장 |

> v2 → v6 주요 변경: 자이로 1개 → 4개 확장(TCA9548A), LCD 16×2 → 20×4, 전원부는 18650 배터리 2개 병렬 구성을 시도했다가 ESP32가 손상되어 현재는 보조배터리 방식으로 운용 중.

## 4. 총점제(Total-Score) 알고리즘

센서 개수만으로 단계를 정하던 기존 교차회로(Cross-Zone) 방식 대신, **센서별 위험도에 가중치를 매겨 점수를 합산하는 총점제**를 적용했다. 화물 이탈과 가장 직결되는 장력을 메인 지표로 배점을 가장 높게 두었다.

| 센서 | 역할 | 경미(Minor) | 심각(Major) | 최대 배점 | 연속 감지 횟수(디바운스) |
|---|---|---|---|---|---|
| 장력 (HX711) | 메인 | 50% 감소 → 2점 | 80% 감소 → 4점 | **4점** | 7회 (×200ms = 1.4초, 벨트 이완은 서서히 진행되므로 가장 길게) |
| 기울기 (MPU6050×4) | 보조 | 300% 변화 → 1점 | 400% 변화 → 2점 | 2점 | 3회 (×200ms = 0.6초, 급격한 기울기 변화는 빠르게 감지) |
| 거리 (VL53L1X) | 보조 | 15% 변화 → 1점 | 30% 변화 → 2점 | 2점 | 5회 (×200ms = 1.0초, 중간 반응속도) |

- **총점 판정 기준**: 0~2점 `NORMAL` / 3~5점 `WARNING`(LCD 경고 + 부저 간헐) / 6점 이상 `DANGER`(LCD 위험 + 부저 연속) — 총점 만점 8점
- 소방설비의 축적형 감지기 원리와 동일하게, 센서마다 서로 다른 연속 감지 횟수를 누적 카운트해 기준을 초과할 때만 점수에 반영 → 단일 센서 오작동이나 순간 노이즈로 인한 오경보 억제
- **장력을 메인(최대 4점)으로 설정한 이유**: 자이로(차체 기울기, 간접적 징후)·거리(화물 위치 이탈, 이미 이탈 시작 후 반응)와 달리, 장력은 래싱벨트를 직접 측정해 화물 이탈 "이전" 단계에서 가장 먼저 반응하는 조기 감지 지표이기 때문
- 4개 자이로는 좌/우 2개씩 평균 낸 뒤 더 큰 쪽을 대표값으로 사용
- 판정 결과는 LCD 20×4 화면(단계 텍스트 + 센서별 % + 자이로 4채널 개별 값)과 부저 강도 차등 출력으로 표시

## 5. 소프트웨어 구조

```
firmware/
  cargo_guardian_code_v6.ino   ESP32 최신 펌웨어 (총점제 + 4자이로 + Wi-Fi UDP 전송)
  legacy/                       v1~v5 이전 버전 (참고용)
python/
  (수신 스크립트)                UDP로 CSV 데이터 수신 → openpyxl로 엑셀 자동 저장
                                (컬럼: 시간, raw값, %값, 센서별 점수, 총점, 최종단계, 경보상태, 자이로1~4 개별 % 등)
data/실험데이터/                 시나리오별 실험 원본 데이터 (xlsx)
docs/                          설계매뉴얼, 실험 분석 보고서, 발표자료, 로직 흐름도 등
```

동작 흐름: ESP32가 200ms 주기로 센서를 읽어 이동평균 필터(5개 샘플) → 영점 대비 변화율(%) 계산 → 총점제 판정 → LCD/부저 출력과 동시에 Wi-Fi UDP로 CSV 문자열을 PC에 브로드캐스트 → Python 스크립트가 실시간 수신해 엑셀에 자동 기록.

## 6. 실험 데이터가 최종 코드에 반영된 과정

### 6-1. 실험 설계 → 데이터 수집

- **독립변수**: 적재물 타입(박스형/파이프형) × 무게(가벼움/중간/무거움) × 주행 상황(정상/급제동/급커브 좌우/노면충격/벨트이완 10%·20%·완전이완)
- **종속변수**: MPU6050 기울기 변화율(%), HX711 장력 감소율(%), VL53L1X 거리 변화율(%) — 모두 영점 대비 변화율
- **파일명 규칙**: `적재물_무게_상황_날짜.xlsx`로 실험마다 개별 저장, 실험 전 매번 영점 리셋 버튼으로 기준값 재설정
- **수집 경로**: ESP32 → Wi-Fi UDP(포트 12345, 200ms 주기) → PC의 Python 수신 스크립트가 openpyxl로 엑셀에 실시간 자동 기록(경고=주황/위험=빨강/리셋=초록 셀 색상 자동 표시)
- **실제 수행 규모**: 박스형(가벼움·중간·무거움 각 8가지 상황) + 파이프형(무거움, 5가지 상황) = **총 29가지 시나리오, 약 3,370행**

| 적재물 | 무게 | 수행 상황 수 | 수집 데이터 |
|---|---|---|---|
| 박스형 | 가벼움 | 8가지 | 약 1,100행 |
| 박스형 | 중간 | 8가지 | 약 850행 |
| 박스형 | 무거움 | 8가지 | 약 950행 |
| 파이프형 | 무거움 | 5가지 | 약 467행 |
| **합계** | | **29가지 시나리오** | **약 3,370행** |

### 6-2. 전처리 → 정규화 → 가중치 → 임계값 역산 (raw 데이터 → 코드 상수로 이어지는 흐름)

1. **이상값 제거**: 직전값 대비 급격한 변화를 노이즈로 판단해 제거
2. **이동평균 필터**: 최근 5개 샘플 평균으로 스무딩 → v6 코드의 `FILTER_SIZE 5`로 그대로 반영
3. **정규화**: raw 값을 절대 수치가 아닌 **영점 대비 변화율(%)**로 변환 — 화물 종류·무게가 달라도 같은 임계값을 쓸 수 있게 하기 위한 설계 의도. 코드의 `tensionPct`, `tiltPct`, `distPct` 계산식이 이 방식
4. **정상/위험 구간 분포 분석** (박스형, 3개 무게 합산 기준):

   | 구분 | 자이로% | 거리% |
   |---|---|---|
   | 정상 구간 95퍼센타일 | 207% | 6.8% |
   | 정상 구간 99퍼센타일 | 312% | 9.1% |
   | 위험(급제동) 95퍼센타일 | 339% | 2.5% |
   | 위험(급커브 좌) 95퍼센타일 | 394% | 3.7% |
   | 위험(급커브 우) 95퍼센타일 | 391% | 126.7% |
   | 위험(노면충격) 95퍼센타일 | 550% | 54.2% |

   파이프형(무거움)은 정상 구간이 자이로 85.8% / 거리 8.0% / 장력 31.4%로, 박스형보다 자이로 변화가 더 안정적(무게 균일 분포)이라는 것도 확인됨.
5. **센서별 가중치 설계**: 초기 설계 단계에서는 장력 0.45 / 거리 0.30 / 자이로 0.25(0~1 스케일, "래싱벨트 직접 측정이 가장 직접적인 이탈 징후"라는 근거)로 잡았고, 실험 데이터 분석 후 이 비율이 **정수 배점(장력 4점 : 자이로/거리 각 2점, 총 8점)** 총점제 방식으로 확정
6. **임계값 역산**: 정상 구간 데이터의 95퍼센타일을 오경보 기준선, 위험 상황 데이터의 95퍼센타일을 감지 기준선으로 잡고 그 사이에서 역산 → 최종 확정된 수치가 v6 코드의 `TILT_MINOR/MAJOR`, `TENSION_MINOR/MAJOR`, `DIST_MINOR/MAJOR`, `ACCUM_TILT/DIST/TENSION`, `SCORE_WARNING/DANGER` 상수들(4장 표와 동일)
7. **재검증**: 임계값 반영 후 재실험 → 오경보율/검출률 재측정 → 필요시 재조정하는 사이클 반복

> 참고: 초기 설계 문서에는 센서별로 샘플링 주기를 다르게(자이로 50ms/거리 200ms/장력 300ms) 두는 안이 있었으나, 분석보고서·v6 코드 모두 **메인 루프 200ms 한 번에 3종 센서를 통합 처리**하는 방식으로 최종 확정되었다. 서류에는 이 최종 방식(루프 200ms + 센서별 축적 횟수로 반응속도 차등) 기준으로 작성하면 된다.

## 7. 검증 결과 (실험데이터 분석보고서 기준)

### 7-1. 목표 검증 기준

쏠림 검출 성공률 80% 이상 / 정상 상태 오경보율 20% 이하 / 연속 동작 안정성 5분 이상 / 반응속도(위험 발생~경보) 1초 이내 / 센서 3종 통합 안정성 / 독립 전원(배터리) 동작 확인 / Wi-Fi 데이터 전송 중 누락 없음

### 7-2. 실제 달성 결과

| 항목 | 결과 |
|---|---|
| 박스 전체 · 정상 주행 오경보율 | **0%** |
| 파이프 무거움 · 정상 주행 오경보율 | **0%** |
| 박스 전체 · 급제동/급커브/노면충격 오경보율 | **0~11%** (목표 20% 이하 달성) |
| 벨트 이완 단계별 감지 | 정상 체결 → `NORMAL` / 이완 10% → `NORMAL`~`WARNING` 경계 / 이완 20% → `WARNING` 발생 / 완전 이완 → `WARNING`~`DANGER` — **이완 정도에 비례한 단계적 감지 확인** |

### 7-3. 결론 요약

- 박스형·파이프형 두 적재물 타입 실험 완료, 총 약 3,370행 데이터 수집
- 데이터 기반 임계값 도출 및 **오경보율 20% 이하 목표 달성**
- 영점 대비 퍼센트 방식 채택으로 화물 종류·무게 무관한 범용 시스템 구현 확인
- 향후 계획(분석보고서 명시): 실제 포터 차량 탑재 테스트, 고속 주행 환경 임계값 미세 보정, TFT 컬러 LCD 및 멀티플렉서 기반 4방위 거리 센서 확장
